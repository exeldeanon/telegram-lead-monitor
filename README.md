# Telegram Lead Monitor

Асинхронный монитор лидов: **юзербот** (Telethon) слушает группы в реальном времени, **бот** (Bot API) отправляет оформленные HTML-алерты в целевой канал/чат со ссылкой на исходное сообщение.

## Архитектура

```
┌─────────────────────┐     ┌──────────────────┐     ┌─────────────────┐
│  Telethon Userbot   │────▶│  Keyword/AI Filter│────▶│  Lead Inbox      │
│  (слушает группы)   │     │  + Dedup + Registry│     │  → Bot/Mini App   │
└─────────────────────┘     └──────────────────┘     └─────────────────┘
```

- **Юзербот** — ваш Telegram-аккаунт, подключённый через Telethon. Слушает все сообщения в группах из `chats.txt`.
- **Бот** — отдельный бот, созданный через @BotFather. Отправляет карточки лидов в `TARGET_CHAT_ID`. Не отправляет личные сообщения автоматически.
- **Lead Inbox** — сохраняет пользователя по Telegram ID, чтобы один и тот же участник не предлагался повторно.
- **Mini App** — мобильный интерфейс для просмотра карточек, предпросмотра шаблона и ручного подтверждения отправки.

## Настройка

### 1. API_ID и API_HASH
Получите на https://my.telegram.org/apps → создайте Desktop-приложение.

### 2. Создайте бота
@BotFather → `/newbot` → скопируйте токен в `BOT_TOKEN`.

### 3. Добавьте бота в целевой чат
Добавьте бота в канал/группу, куда должны приходить алерты (`TARGET_CHAT_ID`). Дайте право на отправку сообщений.

### 4. Узнайте TARGET_CHAT_ID
Добавьте @userinfobot или @getidsbot в целевой чат — он пришлёт ID. Для супергрупп/каналов ID начинается с `-100`.

### 5. Заполните chats.txt
Укажите username'ы или ID групп, которые нужно мониторить:
```
-1001234567890
business_chat_ru
leadgen_marketplace
```
> ⚠️ Юзербот-аккаунт должен быть участником всех этих групп.
> Если `chats.txt` существует, но содержит только комментарии, мониторинг не запускается ни для одного чата — это безопасный режим по умолчанию.

### 6. keywords.txt
15 ключевых фраз уже предзаполнены. Редактируйте по необходимости.

## Первый запуск

```bash
python monitor.py
```

При первом запуске Telethon запросит номер телефона и код подтверждения. Будет создан файл `monitor_session.session`. Повторная авторизация не нужна.

## Как работает

1. Юзербот подписывается на `NewMessage(incoming=True)` во всех чатах из `chats.txt`
2. Каждое сообщение фильтруется:
   - Не своё, не системное, не от бота
   - Из отслеживаемого чата
   - Текст нормализуется (lower, ё→е, очистка)
   - Поиск совпадения с ключевыми фразами
   - Проверка дедупликации (TTL 30 мин, SHA-256 хеш)
3. При совпадении создаётся карточка кандидата. Числовой Telegram ID записывается в общий registry, поэтому пользователь больше не предлагается повторно.
4. Бот отправляет HTML-алерт в `TARGET_CHAT_ID` с кнопками **«Предложить отправку»**, **«Пропустить»** и **«Не связываться»**.
5. «Предложить отправку» открывает предпросмотр заготовки. Личное сообщение отправляется только после второго явного нажатия **«Подтвердить отправку»** или кнопки отправки в Mini App.
6. Алерт содержит: название чата, данные отправителя, триггер, текст сообщения, **прямую ссылку на оригинал**.

### Шаблон сообщения

Шаблон задаётся в `OUTREACH_TEMPLATE`, `config.json` или командой `/settemplate`. Доступны переменные:

```text
{first_name} {last_name} {username} {user_id}
{trigger} {chat_title} {message}
```

Отправка всегда остаётся ручной: монитор только предлагает контакт, а оператор редактирует и подтверждает текст.

### Mini App

Сервер Mini App запускается вместе с монитором на `WEBAPP_HOST:WEBAPP_PORT`. Для открытия внутри Telegram задайте опубликованный HTTPS-адрес в `WEBAPP_URL` и настройте reverse proxy до локального порта. Mini App валидирует `initData` на сервере; для продакшена укажите `OPERATOR_USER_IDS`.

```env
WEBAPP_URL=https://monitor.example.com/
WEBAPP_HOST=127.0.0.1
WEBAPP_PORT=8080
OPERATOR_USER_IDS=123456789
WEBAPP_ALLOW_UNAUTH=false
```

Не включайте `WEBAPP_ALLOW_UNAUTH` на публичном сервере.

## Деплой на Bothost

Bothost подходит для этого проекта, если включить постоянное хранилище. На бесплатном тарифе нельзя надёжно хранить Telethon-сессию и registry между перезапусками; используйте тариф с volume и путь `/app/data`. Bothost требует, чтобы веб-сервер слушал `0.0.0.0` и порт из переменной `PORT`.

1. Создайте локальную String Session:

   ```bash
   py tools/gen_session.py
   ```

2. В Bothost добавьте переменные:

   ```env
   TELEGRAM_API_ID=...
   TELEGRAM_API_HASH=...
   SESSION_STRING=...
   BOT_TOKEN=...
   TARGET_CHAT_ID=...
   OPERATOR_USER_IDS=...
   WEBAPP_URL=https://имя-бота.bothost.ru/
   WEBAPP_HOST=0.0.0.0
   ```

3. Укажите порт `8080` в панели Bothost и включите домен/HTTPS. Dockerfile уже копирует `miniapp/` и сохраняет state в `/app/data`.

4. Запустите деплой из GitHub. В `chats.txt` должны быть реальные ID или username чатов, иначе мониторинг намеренно не будет слушать ни один чат.

Для VPS можно оставить файловую `.session`, но всё равно вынести `state.json`, `lead_registry.json` и сессию в постоянный каталог и поставить reverse proxy с HTTPS для Mini App.

## Обработка ошибок

- **FloodWaitError** — авто-пауза на время от Telegram
- **ConnectionError** — Telethon переподключается автоматически
- **Bot API 429** — повтор после `retry_after`
- Все ошибки логируются без остановки скрипта

## Безопасность

- Никогда не коммитьте `.env` и `*.session`
- `.gitignore` уже настроен
- Используйте отдельный аккаунт для мониторинга
